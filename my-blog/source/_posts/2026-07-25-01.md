我一直想要一个轻量、免费、完全由自己控制的短链接工具。不想依赖第三方平台，也不想为了一个简单的跳转就去租服务器。后来我发现，Vercel 的 vercel.json 配置文件就能完美满足这个需求——不需要写任何后端代码，只要配置几条重定向规则，就能把任意短路径指向任意长 URL。

我的核心思路
我把所有跳转规则都写在 vercel.json 的 redirects 数组里。每个规则包含三个字段：

source：短链接的路径（比如 /b）

destination：要跳转到的目标长链接（可以是任何网站）

permanent：是否永久重定向（我通常用 false，方便后期修改）

举个例子，我随手填了一个 B 站链接作为测试，但实际使用时，我可以把 /gh 指向我的 GitHub，完全看自己需要。

我的实际配置文件
json
{
"redirects": [
{
"source": "/b",
"destination": "https://www.bilibili.com",
"permanent": false
}
]
}
这个只是我练手用的，真正部署后，我会根据需求增删条目。

我是怎么部署的
在本地新建一个项目，里面顺便放 vercel.json 这一个文件。

初始化 Git，推送到我的 GitHub 仓库。

登录 Vercel，导入这个仓库，它会自动识别并部署。

在 Vercel 项目设置里绑定我的自定义域名 share.0x.ccwu.cc。

整个过程不到两分钟，之后我访问 share.0x.ccwu.cc/b 就会跳转到 B 站，所有跳转都由我随时修改 vercel.json 并重新 push 来更新。

我从中得到的启发
这套方案最吸引我的地方是零维护成本和极致的灵活性。我不需要维护数据库，也不用操心服务器性能，Vercel 的全球 CDN 让跳转速度飞快。如果将来链接多了，我还可以用 bulkRedirectsPath 引入外部文件来管理成百上千条规则，或者用 Edge Middleware 做动态跳转（比如根据用户来源跳转不同目标）。
