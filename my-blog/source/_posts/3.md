使用 Cloudflare Pages 部署 Hexo 静态博客完整指南
在众多静态站点托管平台中，Cloudflare Pages 凭借其全球 CDN 加速、自动化构建流程和简便的 Git 集成，成为部署 Hexo 博客的理想选择。本文将系统性地介绍如何将本地编写的 Hexo 站点无缝部署至 Cloudflare Pages，整个过程无需复杂服务器配置，仅需一个 GitHub 仓库即可完成。

一、前期准备
在开始部署之前，请确保本地开发环境已安装以下工具：

Node.js（建议使用 LTS 版本）

Git 版本控制系统

Hexo 命令行工具（可通过 npm install -g hexo-cli 全局安装）

接着，在本地创建一个新的 Hexo 项目：

bash
hexo init my-blog
cd my-blog
npm install
如需测试，可运行 hexo server 并在浏览器访问 http://localhost:4000 预览站点。确认无误后，即可进行后续的版本控制与部署操作。

二、将项目推送至 GitHub
Cloudflare Pages 依赖 Git 仓库作为代码源，因此需要先将本地项目上传至 GitHub。

在 GitHub 上新建一个仓库（建议设置为公开或私有均可，Cloudflare 支持私有仓库）。

在本地项目根目录执行以下命令，初始化 Git 并推送代码：

bash
git init
git add .
git commit -m "初始化 Hexo 博客"
git remote add origin https://github.com/你的用户名/仓库名.git
git push -u origin main
请注意，若默认分支为 master，请相应调整上述命令。

三、在 Cloudflare Pages 中连接仓库
登录 Cloudflare 仪表盘，在左侧菜单中点击 Workers & Pages。

点击 创建应用程序，选择 Pages 选项卡，然后点击 连接到 Git。

授权 Cloudflare 访问您的 GitHub 账号，并从仓库列表中选择刚刚推送的 Hexo 项目。

在“设置构建和部署”页面中，配置以下参数：

生产分支：选择 main（或您的默认分支）

构建命令：填写 npm run build（Hexo 默认构建脚本）

构建输出目录：填写 public（Hexo 生成的静态文件存放目录）

点击 保存并部署，Cloudflare Pages 将自动拉取代码、执行构建命令，并将生成的静态文件发布至全球边缘网络。

四、部署完成与站点访问
部署过程通常在数十秒内完成。成功后，系统会分配一个 *.pages.dev 的默认域名，您可以直接访问该链接查看您的 Hexo 博客。

若您拥有自定义域名，可在项目的 自定义域 选项卡中添加，并按提示完成 DNS 解析（建议使用 Cloudflare 的 DNS 服务以充分利用其安全性与性能优化）。

五、日常更新流程
每次您需要更新博客内容时，只需在本地执行 hexo new "新文章标题" 编写 Markdown 文件，然后重新构建并推送代码：

bash
git add .
git commit -m "发布新文章"
git push
Cloudflare Pages 会自动检测到仓库变更并重新部署，整个过程无需人工干预，实现持续集成与持续交付（CI/CD）。

结语
通过以上步骤，您已成功将 Hexo 静态博客部署至 Cloudflare Pages。该方案不仅提供了快速的全球访问体验，还免去了维护服务器的繁琐工作，让您能够专注于内容创作。无论是个人博客还是项目文档，Cloudflare Pages 都是一个可靠且高效的选择。
