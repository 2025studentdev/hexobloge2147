---
title: 一次 Git 仓库瘦身记录：从几百兆到删掉 .git 重建
date: 2026-11-13 19:01:20
---
事情很简单：之前往仓库里传了十几张高清原图，又塞了几首歌，整个仓库直接膨胀到几百兆。后来把文件删了，结果发现 `.git` 还是很大。

原因也不复杂：Git 删除文件只是在新提交里标记“没了”，但历史提交里的快照还在，那些大文件依然躺在 `.git/objects` 里。`git gc` 只清理不可达对象，历史里还能找到的大文件，它根本不会动。

### 两条路：重写历史，还是直接重建

真要彻底清理，正规做法是用 `git filter-repo` 重写历史，把大文件从所有提交里抹掉，再 `reflog expire` + `gc --prune=now`，最后强制推送。这个方案能保留历史，但操作步骤多，也容易出错。

另一个方案就粗暴多了：**不在乎历史记录，直接删掉 `.git`，重新 `git init` 重建仓库**。历史归零，但当前文件干干净净，操作也简单。这次选了后者。

### 实际执行流程

在仓库根目录：

```bash
# 先记下远程地址和当前分支
git remote -v
git branch --show-current

# 删掉 .git
rm -rf .git        # Windows PowerShell: Remove-Item -Recurse -Force .git

# 重新初始化
git init -b main
git add -A
git commit -m "rebuild repository without large files"

# 顺手查一下有没有漏网大文件
find . -type f -size +10M -not -path './.git/*' -exec ls -lh {} \;

# 重新关联远程并强制推送
git remote add origin <仓库地址>
git push --force -u origin main
```

推完验证一下：

```bash
du -sh .git
git count-objects -vH
```

`.git` 体积回到正常水平，仓库瘦身完成。

### WebStorm 的 Git 图标不见了

删掉 `.git` 之后，这个目录暂时就不是 Git 仓库了，WebStorm 自然不显示 Git 集成。这时候不用去翻一堆设置，直接在项目根目录执行：

```bash
git init -b main
```

`.git` 重新出现后，WebStorm 一般会自动识别；如果还没显示，重新打开一下项目即可。如果之后还有异常，再检查 `Settings → Version Control → Git` 里的 Git 可执行文件路径，或者清一下缓存重启。

### 几个注意点

- `push --force` 会覆盖远程历史，确认没有其他人依赖旧提交。
- 远程如果开了分支保护，需要临时关闭，推完再开。
- 本地分支名要和远程默认分支一致，`main` 还是 `master` 别搞错。
- 想远程立刻彻底变小，最干净的是删掉远程仓库新建空仓库再推。

### 最后：记得重建 Cloudflare 的 webhook

仓库重建、强制推送之后，Cloudflare 的 Git 集成 webhook 可能还绑着旧仓库状态，或者已经失效。**需要去 Cloudflare 控制台重新连接仓库、重建 webhook / 重新授权 Git 集成，然后手动触发一次部署确认能正常构建。** 本地仓库瘦身搞定了，别让部署链路在最后一步掉链子。
